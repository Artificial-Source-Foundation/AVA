# Governance

AVA is maintained through its GitHub repository. This document describes how project decisions and contribution roles are handled without assigning authority to named individuals.

## Roles

- **Contributors** propose code, documentation, tests, reports, and reviews.
- **Reviewers** provide technical feedback on proposed changes.
- **Maintainers** steward repository health: they review or merge changes, manage project settings, moderate project spaces, and make final decisions when consensus is not reached.

These roles describe responsibilities, not employment, ownership, or a guarantee of access.

## Decisions

Changes are proposed through issues and pull requests. Technical discussion should be evidence-based, scoped to project goals, and documented in the relevant issue, pull request, or commit. Maintainers seek workable consensus when practical; when it is not reached, maintainers decide based on correctness, safety, maintainability, compatibility, and available project capacity.

Substantial changes should explain their motivation, alternatives, compatibility implications, test evidence, and documentation impact. Maintainers may defer, close, or request a smaller proposal when a change lacks sufficient evidence or is outside current priorities.

## Conduct and escalation

All participants must follow the [Code of Conduct](CODE_OF_CONDUCT.md). Report conduct concerns privately as described there. Security concerns follow [`SECURITY.md`](SECURITY.md), not public governance channels.

## Changes to this document

Governance changes are made through the normal pull-request process and should explain the reason for the change.
