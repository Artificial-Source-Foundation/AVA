# Security Policy

## Supported versions

Security fixes are evaluated against the current development baseline on the `develop` branch. AVA has no published release support schedule in this repository.

## Reporting a vulnerability

Please do not disclose vulnerabilities in public issues, pull requests, discussions, logs, or chat transcripts.

Use GitHub's private vulnerability reporting for this repository when it is available: open the repository's **Security** tab and choose **Report a vulnerability**. Include a concise description, affected revision or configuration, reproduction steps, impact, and any safe proof of concept. Redact API keys, OAuth tokens, session files, private paths, and other secrets.

If private vulnerability reporting is unavailable or inaccessible, contact a repository owner or maintainer privately through an available GitHub contact channel and ask to establish a confidential reporting channel. Do not publish exploit details while arranging that contact. If you cannot reach a private channel, share only the minimum non-sensitive information needed to request one.

## Handling reports

Maintainers will assess reports, may request clarification through the private channel, and will coordinate any fix or disclosure through that channel where possible. Do not assume a response time, fix, or disclosure date.

For ordinary bugs, usability requests, and documentation corrections, use the public issue templates instead. If you are unsure whether a report is security-sensitive, treat it as private.
