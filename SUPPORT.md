# Support

## Getting help

Start with the documentation map in [`docs/README.md`](docs/README.md), then consult the relevant guides:

- [`docs/USAGE.md`](docs/USAGE.md) for interactive and headless use.
- [`docs/CONFIG.md`](docs/CONFIG.md) for configuration, authentication, models, and local resources.
- [`docs/TESTING.md`](docs/TESTING.md) for building and testing.
- [`docs/diagnostics.md`](docs/diagnostics.md) for diagnostic and support-export guidance.

For reproducible defects or documentation problems, open a public issue using the appropriate template. Include the AVA revision, Linux distribution/environment, exact command or workflow, expected and actual behavior, and redacted logs. Search existing issues first to avoid duplicates.

## Boundaries

Community support is best-effort. Do not include credentials, tokens, private session data, proprietary source, or exploit details in public reports. Route suspected vulnerabilities according to [`SECURITY.md`](SECURITY.md).

For contributions and development setup, see [`CONTRIBUTING.md`](CONTRIBUTING.md).
