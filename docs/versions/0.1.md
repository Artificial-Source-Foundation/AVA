# AVA 0.1

## Goal

Build the first usable AVA: a terminal-only coding agent with a correct backend, a minimal but decent TUI, OpenAI support, safe tools, build/plan modes, permissions, and resumable sessions.

## In Scope

- Terminal-only app.
- Simple TUI with a good-looking composer.
- Tab switches between build mode and plan mode.
- OpenAI provider only for now.
- OpenAI auth through OAuth-token credentials or API key files.
- Provider design leaves room for more providers later.
- MVP tools: read, write, edit, apply_patch, glob, grep, bash, question.
- Permission system modeled after OpenCode/Pi: allow normal work, ask for risky work, deny clearly dangerous work.
- Plan mode blocks source-code edits but may write planning markdown.
- Build mode can edit files without asking unless the action is risky.
- Terminal commands are classified as safe, ask, or deny instead of always asking.
- Sessions are saved and can be resumed.
- Backend is testable without the TUI.

## Implemented Behavior

- `ava` opens a simple TUI when stdin/stdout are terminals.
- Non-TTY usage falls back to a line-oriented shell.
- `ava --continue` resumes the newest session for the current workspace.
- `ava --session <id-or-prefix>` resumes a specific session.
- Sessions are stored under `$XDG_STATE_HOME/ava/sessions` or `~/.local/state/ava/sessions`.
- Config/auth live under `$XDG_CONFIG_HOME/ava` or `~/.config/ava`.
- OpenAI HTTP requests use the local `curl` executable.
- `apply_patch` is a bounded exact-edit tool, not a general fuzzy patch engine.
- `question` is exposed to the model, but 0.1 does not include a modal question UI.

## Out Of Scope

- Web UI.
- Desktop UI.
- Plugins.
- MCP.
- Subagents.
- Multiple providers in the first release.
- Fancy TUI polish beyond a clean minimal experience.
- Full conversation tree UI.
- Automatic compaction unless required for basic functionality.

## Notes For 0.2
