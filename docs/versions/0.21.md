# AVA 0.21 TUI Revival

0.21 is a visual and interaction-quality slice on top of the hardened 0.2 backend. It keeps the same provider, tool, session, and permission authority while making the terminal UI calmer and more agent-native.

## Scope

- Rust AVA-inspired terminal layout with a compact top identity strip, inset transcript, and bottom-pinned composer.
- Role-aware transcript rendering for user, assistant, tool, and error entries.
- Compact tool cards with status markers, tool names, argument summaries, and result summaries.
- Composer with the old AVA elevated surface color, primary-blue left rail, `❯` prompt glyph, mode badge, status metadata, and deterministic cursor placement.
- Slash palette surface above the composer with visible focus, command metadata, and narrow-width fallback.
- Permission approval dock that replaces the composer while active.

## Permission Model

0.21 does not add new permission semantics. Permission prompts still support only:

- `Allow once`
- `Deny`

There are no persistent allow rules, session-wide grants, or deny-with-reason flows in 0.21. Non-TTY permission prompts still fail closed.

## Accessibility Notes

- Focus is represented by non-color text cues plus reverse video where available.
- Permission and slash selections include readable `selected` text when terminal width permits.
- Permission prompts keep `Deny` as the default focused action and hide the composer cursor while active.
- Terminal color contrast depends on the user's terminal theme.
- The fullscreen TUI repaint model is not screen-reader-friendly; users who rely on assistive technology should prefer non-TTY pipe mode, such as `printf '/sessions\n/quit\n' | ava --continue`.

## Verification

Expected checks for this release slice:

```sh
cmake --build build && ctest --test-dir build --output-on-failure
cmake --build build-sanitize && ctest --test-dir build-sanitize --output-on-failure
git --no-pager diff --check -- src/ava/tui/composer.cpp src/ava/tui/runtime.cpp src/ava/tui/terminal.cpp tests/core_tests.cpp README.md docs/USAGE.md docs/versions/0.21.md
```

Manual smoke coverage should include:

- TUI launch in `build` and `plan` modes.
- Slash palette filtering with `/`, a narrowed prefix such as `/g`, and a no-match prefix.
- Cursor editing at the start, middle, and end of the composer input.
- Tool cards for running, success, and error states.
- Permission prompt deny paths with `Esc`, `D`, and `Space` while `Deny` is focused.
- Permission prompt allow-once path with `A` and with `Enter` after moving focus to `Allow once`.
- Narrow terminal resize around 36 columns and the minimum supported 20-column layout.
- Cursor hidden while the permission dock is active and restored after resolution.
- Non-TTY smoke, for example `printf '/help\n/quit\n' | ava --mode build`.
