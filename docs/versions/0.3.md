# AVA 0.3 Workflow Depth

This is a historical milestone plan for the 0.3 release line. It records the scope boundaries used at that point in the project; current capabilities may exceed this document. For current CLI behavior, see `README.md`, `docs/core/usage.md`, and `docs/headless-protocol.md`.

## Goal

Make AVA better at sustained coding sessions without expanding into post-0.3 platform features. The release focuses on context lifecycle, real interactive question flow, session export, and TUI workflow visibility.

0.3 should use external reference systems as behavior references only. Do not copy their architecture or code. Take small native C++ slices that fit AVA's current provider, session, permission, tool, and custom TUI boundaries.

## Release Shape

- Small cohesive release.
- Two coordinated tracks: backend workflow depth and frontend/TUI workflow visibility.
- Backend owns stable session entries, command behavior, permission semantics, and tool contracts.
- Frontend consumes those contracts and does not invent session JSON shapes, permission meanings, or export formats independently.

## Reference Comparison Summary

### Useful Backend Ideas

- Agent loop hooks for context transformation, follow-up messages, cancellation, and tool lifecycle events.
- Session compaction entries with structured summaries and recent-context retention.
- Context file discovery for `AGENTS.md`/`CLAUDE.md` with path annotations and deduplication.
- Print/non-TTY mode for one-shot automation.
- Question tools that degrade safely when no UI is available.

### Useful Frontend Ideas

- Question modal with selectable options, custom answer input, and clear submit/cancel controls.
- Command palette with categories, suggested actions, and help text.
- Context/session visibility in the main UI without a full session tree.
- Export UX with basic options.
- Transcript workflow improvements for long sessions.

## Backend Track

Headless backend protocol contracts live in [`../headless-protocol.md`](../headless-protocol.md); this 0.3 plan should reference that file rather than duplicating event or RPC shapes.

### In Scope

- Harden the main agent loop around context lifecycle and long-running turn safety.
- Add backend-owned context file loading for local project instructions, starting with `AGENTS.md` and optionally `CLAUDE.md` if the implementation remains small.
- Add manual compaction support with persisted compaction session entries.
- Add backend compaction APIs that `/compact` can call later; TUI and CLI slash-command wiring are separate frontend-track work.
- Replace the placeholder `question` tool behavior with a synchronous resolver contract, similar to the existing permission resolver, that the TUI can satisfy and non-TTY mode can fail safely.
- Add session export formatting owned by backend code, with markdown as the initial format and no TUI/CLI file-destination wiring in the backend batch.
- Add a small reference-inspired backend slice only where it directly supports 0.3: context transform before provider calls, cancellation/error boundaries, or structured loop status events.

### Backend Non-Goals

- Full automatic compaction unless manual compaction exposes a trivial and safe threshold hook.
- Full session tree UI, branching, forking, or branch summaries.
- Plugin systems, custom UI extensions, subagents, MCP, LSP, web fetch, or multiple providers.
- Persistent permission-rule management.
- Rich diff/patch review UI or edit-review workflows.
- Protocol expansion beyond the current print/RPC MVP unless needed as the smallest support for export or non-TTY question behavior.

## Frontend Track

The frontend agent should plan from this section and the backend contracts below, but should produce its own implementation plan.

### In Scope

- Improve the TUI for longer sessions: clearer transcript flow, active turn status, and context visibility.
- Add `/compact` command UX that calls backend compaction and renders compaction entries in the transcript.
- Improve the slash command palette design when opening `/`: categories, suggestions, and clearer command descriptions.
- Add question modal UX for the backend `question` request contract.
- Add `/export` UX that calls backend session export formatting.
- Improve session workflow and transcript command palette design without implementing a full session tree.
- Compare external reference interaction patterns and choose small terminal-native slices that fit AVA's custom TUI.

### Frontend Non-Goals

- Full theme system.
- Plugin-extensible sidebar or custom UI slots.
- Full session tree, branching, forking, or timeline navigation.
- Persistent permission-rule management UI.

## Backend-To-Frontend Contracts

### Context Visibility

Backend should expose a stable summary of loaded context sources:

- path
- source type, such as workspace or global
- byte or character count when cheap
- status, such as loaded, skipped, or error

The TUI may display this as a compact status panel or command output. The TUI should not parse system prompts to infer context.

### Compaction

Backend should own compaction session entries. A compaction entry should include:

- summary text
- reason, such as manual
- timestamp
- approximate before/after context size when cheap
- recent-turn retention metadata when available

The TUI should render compaction entries as transcript events and expose `/compact` as a command that calls backend behavior.

### Question Tool

Backend should define the request and answer shape for structured questions:

- question text
- optional short header
- options
- single-select or multi-select
- whether custom text is allowed

Backend should expose this through a synchronous resolver callback on the agent/tool context, analogous to the current permission resolver. Interactive TUI mode can later answer the request through a modal. Non-TTY mode should fail closed or return a clear unavailable result unless an explicit future automation format is added. This does not require a resumable agent loop or async UI architecture in 0.3.

### Export

Backend should own transcript formatting. Initial export options should stay small:

- format: markdown
- include tool details: yes/no
- include assistant metadata if already stored

The TUI should collect options and destination, but not duplicate formatting logic.

## Milestones

### M0: Planning And Contract Review

- Confirm backend and frontend scope boundaries.
- Review external reference systems for small useful slices.
- Keep this document as the shared coordination source.

### M1: Backend Context Loading And Loop Context Boundary

- Discover and load context instruction files.
- Inject loaded context through backend-owned prompt construction.
- Keep context assembly in backend modules so the TUI does not parse or mutate system prompts.
- Add tests for discovery, deduplication, and safe missing-file behavior.

### M2: Backend Manual Compaction

- Add compaction session entry support.
- Add manual compaction backend API; `/compact` routing is frontend/integration wiring.
- Summarize through the provider only if the existing provider request path can be reused without a broad refactor.
- If provider summarization is not a small reuse, persist an unavailable/manual compaction entry with clear metadata rather than widening scope.
- Update agent-loop message reconstruction so compaction entries are summarized or skipped deliberately instead of serialized as normal chat entries.
- Add tests for session persistence and context reconstruction behavior.

### M3: Backend Question Contract

- Replace the placeholder `question` tool response with a real request/answer path.
- Use a resolver callback on the tool or agent context rather than a resumable loop rewrite.
- Preserve fail-closed non-TTY behavior.
- Add tests for request validation, answer serialization, cancellation, and unavailable UI.

### M4: Backend Export Formatter

- Add markdown transcript formatting.
- Add backend export APIs; `/export` routing and file-destination UX are frontend/integration wiring.
- Add tests for transcript escaping, tool detail inclusion, and empty/minimal sessions.

### M5: TUI Workflow Slice

- Add context visibility, `/compact`, question modal, `/export`, command palette polish, and transcript improvements based on backend contracts.

### M6: Release Hardening

- Keep normal and sanitizer tests passing.
- Update `README.md` and `docs/core/usage.md` to match shipped behavior.
- Run review checkpoints for backend contracts, TUI workflow, and final integration.

## Validation Targets

Expected baseline checks:

```sh
cmake --build build && ctest --test-dir build --output-on-failure
cmake --build build-sanitize && ctest --test-dir build-sanitize --output-on-failure
git --no-pager diff --check -- README.md docs/core/usage.md docs/versions/0.3.md src/ava tests
```

Manual smoke coverage should include:

- TUI launch in `build` and `plan` modes.
- `/compact` command on a short session and a longer session.
- `question` tool in interactive mode.
- `question` tool in non-TTY mode.
- `/export` on a resumed session.
- Session resume after compaction entries exist.
- Context visibility when workspace context files exist and when they do not.

## Reopen Planning If

- Compaction requires a larger provider abstraction change than expected.
- Context loading creates compatibility risk with existing sessions or system prompts.
- Question plumbing requires a broad TUI/app architecture rewrite.
- Export needs filesystem write behavior outside the approved file tool/session layer.
- A frontend need conflicts with backend-owned session, permission, or command semantics.
