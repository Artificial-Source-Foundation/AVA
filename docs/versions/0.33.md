# AVA 0.33 Backend Maturity Ledger

AVA 0.33 tracks backend robustness and content-boundary work in small, verifiable slices. Keep this file updated as each slice lands so the release state is visible without reading commit history.

## Scope

- Keep backend events and command results semantic, typed, and layout-free.
- Keep frontend-owned content adaptation separate from terminal drawing.
- Reduce large coordinator files by moving cohesive helpers into narrow modules.
- Strengthen headless CLI/RPC coverage so backend behavior is testable without the TUI.
- Preserve provider, tool, permission, session, and config safety boundaries.

## Non-Goals

- Do not polish or redesign the visual TUI in this release ledger.
- Do not add terminal layout concepts to backend event or command contracts.
- Do not copy reference UI layouts, screens, or code.

## Slice Ledger

### S1: Semantic Content Boundary

- Added a layout-free frontend text model under `src/ava/tui/text.*`.
- Added Markdown/plain-text adaptation into typed text runs before rendering.
- Kept backend-facing data as semantic events plus Markdown/plain text.
- Covered text-run invariants, newline splitting, Markdown fallback, and plain-text round trips.

### S2: Permission And Question Payloads

- Extended semantic permission/question payloads where needed for frontend prompts.
- Kept prompt fields semantic: action text, options, selection metadata, secret/custom flags, and copyable text.
- Avoided backend-owned layout instructions for prompt presentation.

### S3: Headless Runtime Coverage

- Added deterministic CLI/RPC coverage for permission grants, provider errors, compaction, questions, and tool failures.
- Use live headless CLI smoke tests for read-only provider/tool integration when credentials are available.
- Keep live provider runs separate from deterministic CTest coverage.

### S4: Session Command Formatting Split

- Moved `/stats` text formatting out of `src/ava/app/command_sessions.cpp`.
- New owner: `src/ava/app/command_session_format.*`.
- `command_sessions.cpp` now stays closer to command coordination while stats formatting rules are directly testable.
- Added coverage for unavailable token/byte usage and incomplete cost text.

### S5: Tool Event Projection Split

- Moved tool timeline/runtime-event projection out of `src/ava/app/command_tools.cpp`.
- New owner: `src/ava/app/command_tool_events.*`.
- Slash-tool command routing now stays separate from semantic tool event construction.
- Added focused assertions for semantic tool start/result event fields emitted by `/glob`.

### S6: Runtime Event Payload Split

- Moved runtime-event payload JSON and stream alias projection out of `src/ava/app/events.cpp`.
- New owner: `src/ava/app/event_payload.*`.
- Event bus/envelope coordination now stays separate from semantic payload projection.
- Added direct coverage for payload helper output and top-level alias projection.

### S7: Auth File JSON Split

- Moved auth-file JSON member parsing, rendering, and provider credential object formatting out of `src/ava/config/auth.cpp`.
- New owner: `src/ava/config/auth_file_json.*`.
- Auth file locking, safe reads, atomic writes, credential discovery, and refresh flow now stay separate from JSON merge helpers.
- Added direct coverage for raw auth member parsing, deterministic rendering, provider credential formatting, and malformed member rejection.

### S8: Anthropic Request Builder Split

- Moved Anthropic request body construction and request validation out of `src/ava/provider/anthropic_provider.cpp`.
- New owner: `src/ava/provider/anthropic_request.*`.
- Provider transport/auth wiring and response parsing now stay separate from request serialization rules.
- Added direct coverage for cache controls, reasoning options, tool schema mapping, and unmatched native tool-use validation.

### S9: MCP Protocol Helper Split

- Moved MCP JSON-RPC request formatting, frame parsing, response-id parsing, tool-name validation, and tool-result text extraction out of `src/ava/mcp/stdio_client.cpp`.
- New owner: `src/ava/mcp/protocol.*`.
- `McpStdioClient` still owns process launch, pipe I/O, timeouts, cancellation, stderr draining, and shutdown.
- Added direct tests for JSON-RPC formatting, frame headers, Content-Length validation, response IDs, JSON depth caps, tool names, and tool-result content extraction.

### S10: Plugin Protocol Helper Split

- Moved plugin protocol request formatting, response parsing, boolean parsing, and JSON depth checks out of `src/ava/plugin/runner.cpp`.
- New owner: `src/ava/plugin/protocol.*`.
- `PluginProcess` still owns process launch, pipe I/O, timeout/cancellation handling, stderr draining, and shutdown.
- Added direct tests for initialize/tool/command/event request formatting, handshake parsing, result parsing, response ID matching, and JSON depth caps.

### S11: Provider Tool Argument Helper Split

- Moved provider-tool argument extraction, control-byte/NUL rejection, optional size/boolean parsing, `no_ignore` rejection, and workspace path resolution out of `src/ava/agent/tool_dispatcher.cpp`.
- New owner: `src/ava/agent/tool_arguments.*`.
- `ToolDispatcher` still owns tool routing, registry lookup, cancellation checks, and execution coordination.
- Added direct tests for required strings, safe/text strings, NUL/control-byte rejection, size clamping, strict booleans, provider `no_ignore` rejection, and workspace-relative path resolution.

### S12: Neutral Baseline Docs Cleanup

- Renamed the backend maturity acceptance document to `docs/roadmap/backend-maturity-baseline.md`.
- Reworded AVA-owned docs to use neutral external-reference language and avoid product-name coupling in roadmap text.
- Removed stale explicit reference-code path lists from roadmap docs so they do not drift when local reference checkouts move.
- Left `docs/reference-code/` untouched because those directories are imported reference material, not AVA-authored docs.

### S13: Neutral Legacy Auth Naming Cleanup

- Renamed the AVA-facing legacy auth compatibility helper to `legacy_compatible_auth_path`.
- Preserved the existing fallback auth-file lookup behavior while removing product-name coupling from source identifiers and test labels.
- Updated auth/XDG tests to construct the compatibility path through neutral helpers and keep the security checks for fallback auth file permissions.

### S14: Auth Storage Helper Split

- Split low-level auth-file storage, safe reads, lock acquisition, and atomic replacement out of `src/ava/config/auth.cpp`.
- New owner: `src/ava/config/auth_storage.*`.
- `auth.cpp` now focuses on provider credential parsing, credential source precedence, refresh decisions, and provider-facing credential resolution.
- Added direct auth-storage tests for missing-file reads, private file reads, broad-permission rejection/override, lock acquisition, and atomic replacement.

### S15: Plugin Stream Buffer Split

- Split plugin stdout record buffering and bounded stderr tail logic out of `src/ava/plugin/runner.cpp`.
- New owner: `src/ava/plugin/stream_buffers.*`.
- `PluginProcess` still owns process launch, pipe polling, cancellation, request/response exchange, shutdown, and protocol error context.
- Added direct tests for CRLF record extraction, partial-record retention, byte-cap detection, retained stdout trimming, and stderr tail truncation.

### S16: Plugin Process Support Split

- Split plugin Unix fd/signal/process helper code out of `src/ava/plugin/runner.cpp`.
- New owner: `src/ava/plugin/process_support.*`.
- `PluginProcess` still owns lifecycle policy, request/response sequencing, protocol validation, cancellation behavior, stderr diagnostics, and shutdown decisions.
- Existing plugin runner tests continue to cover subprocess launch, pipe setup, stderr collection, startup timeout, cancellation, process-exit diagnostics, oversized output handling, tool calls, command calls, event observation, and shutdown.

### S17: Apply Patch Staging Helper Split

- Split apply-patch temp-write staging, cleanup, permission-copy, path de-duplication, and staged-file commit helpers out of `src/ava/agent/tool_dispatcher.cpp`.
- New owner: `src/ava/agent/patch_staging.*`.
- `ToolDispatcher` still owns provider argument parsing, permission checks, diff generation, mutation locking, cancellation boundaries, tool result JSON, and registry dispatch.
- Added focused helper coverage for staged temp writes, permission preservation, commit behavior, and cleanup after a later staging failure.

### S18: Tool Result JSON Helper Split

- Split raw provider-facing tool result JSON helpers out of `src/ava/agent/tool_dispatcher.cpp`.
- New owner: `src/ava/agent/tool_result_json.*`.
- `ToolDispatcher` still owns tool execution flow, provider argument validation, permission/cancellation handling, and result payload status selection.
- Added direct helper coverage for boolean literals, structured error JSON, changed-file metadata, diff metadata, and spill metadata.

### S19: Question Answer Validation Split

- Split question-answer bounds validation out of `src/ava/agent/tool_dispatcher.cpp`.
- New owner: `src/ava/agent/question_answer_validation.*`.
- `ToolDispatcher` still owns invoking the resolver, handling resolver failures, and serializing successful question answers into provider tool results.
- Added direct helper coverage for valid answers, too many selected options, oversized selected option text, and oversized custom text.

### S20: MCP Process Support Split

- Split MCP stdio fd, pipe, signal, wait, retry, timeout, close, and exit-status helpers out of `src/ava/mcp/stdio_client.cpp`.
- New owner: `src/ava/mcp/process_support.*`.
- `McpStdioClient` still owns server launch policy, initialization, JSON-RPC request/response handling, frame buffering, cancellation, stderr bounds, and shutdown sequencing.
- Added direct helper coverage for pipe creation, retrying read/write syscalls, fd close/reset behavior, and remaining-timeout calculation.

### S21: Session Entry Codec Split

- Split session JSONL line encoding/decoding, bounded line reads, entry-version checks, session-id validation, and parent-id validation out of `src/ava/session/session_store.cpp`.
- New owner: `src/ava/session/session_entry_codec.*`.
- `SessionStore` still owns session paths, directory/file permissions, symlink and regular-file checks, opening, appending, loading, and listing stores.
- Added direct codec coverage for encode/decode round trips, CRLF and unterminated line reads, invalid IDs, raw newline rejection, and unsupported future-version errors.
