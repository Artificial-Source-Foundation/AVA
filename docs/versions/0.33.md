# AVA 0.33 Backend Maturity Ledger

AVA 0.33 tracks backend robustness and content-boundary work in small, verifiable slices. Keep this file updated as each slice lands so the release state is visible without reading commit history.

## Scope

- Keep backend events and command results semantic, typed, and layout-free.
- Keep frontend-owned content adaptation separate from terminal drawing.
- Reduce large coordinator files by moving cohesive helpers into narrow modules.
- Strengthen headless CLI/RPC coverage so backend behavior is testable without the TUI.
- Preserve provider, tool, permission, session, and config safety boundaries.

## Non-Goals

- Do not polish or redesign the visual TUI in this release ledger.
- Do not add terminal layout concepts to backend event or command contracts.
- Do not copy reference UI layouts, screens, or code.

## Slice Ledger

### S1: Semantic Content Boundary

- Added a layout-free frontend text model under `src/ava/tui/text.*`.
- Added Markdown/plain-text adaptation into typed text runs before rendering.
- Kept backend-facing data as semantic events plus Markdown/plain text.
- Covered text-run invariants, newline splitting, Markdown fallback, and plain-text round trips.

### S2: Permission And Question Payloads

- Extended semantic permission/question payloads where needed for frontend prompts.
- Kept prompt fields semantic: action text, options, selection metadata, secret/custom flags, and copyable text.
- Avoided backend-owned layout instructions for prompt presentation.

### S3: Headless Runtime Coverage

- Added deterministic CLI/RPC coverage for permission grants, provider errors, compaction, questions, and tool failures.
- Use live headless CLI smoke tests for read-only provider/tool integration when credentials are available.
- Keep live provider runs separate from deterministic CTest coverage.

### S4: Session Command Formatting Split

- Moved `/stats` text formatting out of `src/ava/app/command_sessions.cpp`.
- New owner: `src/ava/app/command_session_format.*`.
- `command_sessions.cpp` now stays closer to command coordination while stats formatting rules are directly testable.
- Added coverage for unavailable token/byte usage and incomplete cost text.

### S5: Tool Event Projection Split

- Moved tool timeline/runtime-event projection out of `src/ava/app/command_tools.cpp`.
- New owner: `src/ava/app/command_tool_events.*`.
- Slash-tool command routing now stays separate from semantic tool event construction.
- Added focused assertions for semantic tool start/result event fields emitted by `/glob`.

### S6: Runtime Event Payload Split

- Moved runtime-event payload JSON and stream alias projection out of `src/ava/app/events.cpp`.
- New owner: `src/ava/app/event_payload.*`.
- Event bus/envelope coordination now stays separate from semantic payload projection.
- Added direct coverage for payload helper output and top-level alias projection.

### S7: Auth File JSON Split

- Moved auth-file JSON member parsing, rendering, and provider credential object formatting out of `src/ava/config/auth.cpp`.
- New owner: `src/ava/config/auth_file_json.*`.
- Auth file locking, safe reads, atomic writes, credential discovery, and refresh flow now stay separate from JSON merge helpers.
- Added direct coverage for raw auth member parsing, deterministic rendering, provider credential formatting, and malformed member rejection.

### S8: Anthropic Request Builder Split

- Moved Anthropic request body construction and request validation out of `src/ava/provider/anthropic_provider.cpp`.
- New owner: `src/ava/provider/anthropic_request.*`.
- Provider transport/auth wiring and response parsing now stay separate from request serialization rules.
- Added direct coverage for cache controls, reasoning options, tool schema mapping, and unmatched native tool-use validation.

### S9: MCP Protocol Helper Split

- Moved MCP JSON-RPC request formatting, frame parsing, response-id parsing, tool-name validation, and tool-result text extraction out of `src/ava/mcp/stdio_client.cpp`.
- New owner: `src/ava/mcp/protocol.*`.
- `McpStdioClient` still owns process launch, pipe I/O, timeouts, cancellation, stderr draining, and shutdown.
- Added direct tests for JSON-RPC formatting, frame headers, Content-Length validation, response IDs, JSON depth caps, tool names, and tool-result content extraction.
