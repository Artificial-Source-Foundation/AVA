# AVA 0.70 Reasoning And Model Lifecycle

AVA 0.70 is the reasoning, model-control, and session-lifecycle closeout. The bounded 0.70 work is bundled into the 0.65 provider-hardening pass because the runtime behavior already exists and the closeout is limited to docs, focused tests, and small export polish.

This document tracks release-position status, not a shipped runtime version. Update the compiled project/runtime version only in a dedicated release-bump slice.

## Status

- Frontend-visible reasoning lifecycle events already flow through provider-neutral runtime events.
- Reasoning controls are validated against active model/provider metadata before request building.
- Durable model-change and reasoning-change session entries exist and are exported; reasoning-change export now includes `budget_tokens` when present.
- Provider-native reasoning replay is preserved where supported and model switching rejects incompatible replay windows before appending a `model_change` entry.
- Bundled 0.70 work is documentation/protocol examples and focused regression coverage that proves the existing behavior.

## Goal

Make reasoning and mid-session model changes first-class backend concepts instead of partial metadata or provider-specific behavior.

## Scope

- Emit frontend-visible reasoning lifecycle events for supported providers: start, delta/update, end, and redacted/error states where applicable.
- Wire reasoning/thinking controls into provider request builders only when the selected model declares support.
- Document and harden RPC and command flows for reasoning controls so headless clients cannot request unsupported thinking modes.
- Persist reasoning-control changes and model-change entries in session JSONL with enough metadata for audit, replay, and export.
- Preserve provider-native reasoning storage and replay while keeping session files inspectable.
- Harden mid-session model switching across tool-capable, non-tool, reasoning, non-reasoning, same-family, and cross-family providers.
- Add protocol/golden tests for model listing, model switching, reasoning-control changes, and reasoning event shapes.

## Exit Criteria

- Clients can display reasoning without parsing provider-specific raw events.
- Unsupported reasoning controls are hidden or rejected before a provider request is built.
- Session export shows model and reasoning-control changes clearly, including reasoning budget metadata when present.
- Provider replay either preserves native reasoning safely or prunes/fails with an actionable error before invalid requests are sent.
- RPC protocol docs describe model and reasoning-control semantics with stable examples.

## Bundled Into 0.65

0.70 does not need a broad standalone runtime implementation pass. Keep it split out only if future work expands beyond:

- `docs/headless-protocol.md` examples for model listing/switching, reasoning controls, state output, and unsupported-control failures.
- Focused provider/runtime/session tests for the already-implemented behavior.
- Small export polish such as reasoning budget display.

## Not In This Cut

- New provider families beyond the 0.65 provider-hardening target.
- Plugin marketplace or remote plugin install.
- Full session tree UI.
