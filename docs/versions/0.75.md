# AVA 0.75 Extension Foundation Alpha

AVA 0.75 is the source-backed alpha cut for the stable local extension foundation. It builds on the 0.60 command-registry seam and turns plugin/MCP work into explicit bounded contracts.

This document tracks release-position status, not a shipped runtime version. Update the compiled project/runtime version only in a dedicated release-bump slice.

## Goal

Allow local extensions to contribute tools, slash/backend commands, prompt templates, skills, and MCP-backed capabilities through bounded AVA-owned registry, permission, event, audit, and cancellation paths.

## Scope

- Validate unified command discovery and invocation across built-ins, project/global prompt commands, skills, plugin commands, and MCP prompt commands.
- Define the plugin manifest schema: plugin id, display name, version, API version, entrypoint, contribution declarations, requested capabilities, and default enabled/disabled state.
- Implement explicit plugin discovery and enablement rules for global and project config paths; project plugin code must not execute before explicit enablement.
- Stabilize the out-of-process JSONL plugin handshake, API version negotiation, startup timeout, per-request timeout, stderr capture, bounded stdout, malformed-record handling, cancellation, and shutdown behavior.
- Route plugin tool, command, prompt, and skill contributions through the same registry and permission model used by built-in operations.
- Add extension-scoped permission and audit labels that include plugin id, contribution id/type, requested capability, decision, resolver source, and executed core operation.
- Extend MCP stdio hosting for the 1.0 foundation scope: initialize, tools/list, tools/call, prompts/list, and prompts/get behind explicit permissioned configuration. Keep resources/list and resources/read deferred until a bounded read-style design lands; that read-style slice later landed behind `mcp.resource.read`.

## Exit Criteria

- A fake plugin can register at least one tool and one command through the extension path.
- Plugin-contributed operations cannot mutate files, run commands, fetch network resources, or touch external paths without policy coverage.
- MCP tool and prompt discovery/invocation are covered by fake-server tests and headless RPC smokes.
- Plugin and MCP failures produce contained AVA errors, not crashes or corrupted session files.
- Extension contracts are documented enough that 0.80 can freeze and harden them instead of redesigning them.

## Not In This Cut

- Plugin package manager, marketplace, or remote install flow.
- In-process native plugin ABI.
- MCP resources/list and resources/read in the 0.75 cut; a bounded read-style resource slice later landed behind `mcp.resource.read`.
- Stable authoring docs, sample plugin packaging, and the full plugin/MCP failure matrix; those belonged to 0.80 stabilization. The authoring docs, sample, compatibility policy, golden fixtures, focused failure coverage, read-style MCP resources, and 1.0 release evidence have since landed through 0.80, 0.90, and 1.0, while advanced MCP resources, marketplace, native ABI, and hard sandbox guarantees remain post-1.0 work.
- Cross-platform hard sandbox guarantees for arbitrary plugin executables.
