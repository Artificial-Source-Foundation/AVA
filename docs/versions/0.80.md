# AVA 0.80 Extension API Stabilization

AVA 0.80 is the historical stabilization cut for the local plugin and MCP API. It converted the source-backed 0.75 extension alpha into the v1-compatible local extension contract that shipped with AVA 1.0.

This document is release-position evidence, not a shipped runtime version by itself. The compiled project/runtime version has since advanced to `1.0.0`.

Current status: the plugin authoring guide, minimal checked-in sample, contract-hardening pass, and OpenAI 5.5 manual headless release-validation pass are implemented. `docs/plugin-system.md` documents the supported local authoring path, `examples/plugins/todo/` contains the sample, and the plugin test suite exercises the sample manifest, static resources, protocol path, and successful sample entrypoint execution. `ava_cli.headless_rpc_sample_plugin` copies the checked-in sample as project plugin assets and verifies headless RPC discovery, inspection, validation, static resources, enable/disable state, and fail-closed command execution without starting the sample process. The compatibility policy lives in [`docs/plugin-compatibility-policy.md`](../plugin-compatibility-policy.md). Minimal golden fixtures cover representative plugin/MCP tool schemas and permission audit JSON shape; focused tests cover MCP denial audit linkage plus selected stdio failure containment. Manual OpenAI 5.5 smokes covered print/JSON events, read/search tools, webfetch allow and denial paths, RPC permission replies, multi-turn state/session behavior, and direct RPC compaction. Later 0.90/1.0 release evidence accepted Kimi-for-coding as the additional provider path and carried this extension contract into the shipped 1.0 runtime.

## Goal

Freeze the small 1.0 plugin/MCP contract with docs, samples, diagnostics, compatibility policy, and failure coverage strong enough for users and AI assistants to author local extensions without reading AVA C++ internals.

## Scope

- Continue closing the remaining plugin failure matrix and contract coverage: crash, hang, startup timeout, request timeout, malformed JSONL, unsupported API version, invalid schemas, invalid results, excessive output, stderr flooding, cancellation, restart, disable, and last-failure diagnostics.
- Continue MCP lifecycle coverage for the implemented 1.0 foundation scope: launch, initialize, list, call/get, permission denial, timeout, cancellation, malformed output, restart, and shutdown. MCP `resources/list` and `resources/read` remained explicitly deferred in this cut until a separate read-style command/tool design landed later behind `mcp.resource.read`.
- Keep plugin diagnostics commands for list, inspect, enable, disable, manifest validation, static resources, and last-failure reporting covered by docs and tests.
- Keep the AI-friendly authoring guide and checked-in sample plugin aligned with regression tests as the API changes.
- Keep the v1 compatibility policy, deprecation path, supported contribution types, and schema-change rules aligned with tests and docs.
- Keep the minimal AVA 0.80 golden fixtures for representative plugin/MCP schemas and audit shapes current, and add narrowly scoped fixtures when stable serialized shapes intentionally change.
- Re-audit permission and audit coverage for plugin and MCP operations as new contribution paths or diagnostics land.

## Exit Criteria

- A developer or AI assistant can build a minimal plugin from docs and sample files without studying AVA internals. This is satisfied for the current local plugin surface by `docs/plugin-system.md` and `examples/plugins/todo/`; keep it true as the contract hardens.
- Plugin crashes, hangs, malformed output, unsupported versions, invalid results, and cancellation are all contained and covered by regression tests.
- MCP tools and prompts are exposed through bounded AVA registry paths with documented permissions; MCP resources were explicitly deferred in this cut, before the later read-style `mcp.resource.read` resource slice landed.
- The plugin/MCP API is stable enough to carry into 1.0 with only bug fixes and compatibility-preserving additions.

## Not In This Cut

- Marketplace or remote installation.
- Complex remote MCP OAuth/subscriptions/sampling/pagination.
- Built-in multi-agent/subagent orchestration.
