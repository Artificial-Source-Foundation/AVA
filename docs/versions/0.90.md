# AVA 0.90 V1 Release Candidate

AVA 0.90 is the v1 release-candidate re-audit cut. It should be feature-freeze work: compatibility, verification, documentation, test evidence, and release polish rather than new backend surface area.

This document is the release-candidate evidence ledger that justified the shipped `1.0.0` runtime bump. It remains historical support for the 1.0 backend MVP release.

## Goal

Prove that the v1 backend MVP is coherent, stable, documented, and upgrade-ready before declaring 1.0.

## Scope

- Re-audit `docs/roadmap/backend.md`, `docs/product/backend-capabilities-1.0.md`, `docs/headless-protocol.md`, `docs/USAGE.md`, `docs/TESTING.md`, and all version docs against current code.
- Freeze RPC protocol v1 compatibility for the 1.0 cut, including dynamic command, model, reasoning, plugin, and MCP schemas.
- Resolve or explicitly defer every remaining `Partial` or `Planned` row in `docs/product/backend-capabilities-1.0.md` that is marked required for 1.0.
- Run full release verification: configure, build, full CTest, focused headless smokes, sanitizer build when practical, and `git --no-pager diff --check`.
- Run live provider smokes for the providers claimed as production-quality.
- Verify session JSONL migration/rejection behavior, export readability, permission audit entries, model-change entries, reasoning entries, and plugin/MCP audit labels.
- Decide the final runtime version bump path from the current documented line to 1.0.

Manual/live evidence:

- OpenAI 5.5 headless validation has already covered print JSON events, read/search tools, webfetch allow/deny, RPC permission replies, grant lifecycle, multi-turn state/messages/stats, and direct RPC compaction.
- 0.90 provider discovery verified Anthropic, Kimi, Moonshot, and OpenRouter-compatible built-in profiles are selectable with RPC `list_models` and `set_model`.
- Kimi-for-coding live prompt smoke now passes through normal AVA auth/config and provides one non-OpenAI provider evidence path for 0.90.
- Anthropic live smoke reached the provider endpoint but was auth-blocked by a provider `401` invalid API-key response from the configured credential. Moonshot and OpenRouter-compatible prompt smokes remain credential-blocked by missing auth in AVA config.
- Additional non-OpenAI prompt smokes remain useful release evidence. Do not read or print credential files while collecting that evidence.
- Live smoke failures must be classified as auth/config, provider/rate-limit, network, or AVA regression before they influence 1.0 readiness.

Current readiness status:

- The previous provider-evidence blocker is resolved for one non-OpenAI path by the passing Kimi-for-coding live prompt smoke.
- Kimi-for-coding is accepted as the additional production-quality provider evidence for 1.0, and the release-bump slice moved the compiled runtime to `1.0.0`.
- Anthropic remains auth-blocked by the configured key, and Moonshot/OpenRouter-compatible prompt smokes remain credential-blocked. Treat those as follow-up provider-breadth evidence unless the product decision changes and Anthropic becomes required for a future provider-readiness gate.

## Exit Criteria

- No known blocking test failure remains.
- No required 1.0 capability is still `Planned`; remaining `Partial` items are either completed, explicitly narrowed, or moved to post-1.0 docs.
- RPC/protocol docs and golden tests agree.
- Provider, reasoning, command, plugin, MCP, session, permission, and tool docs match implementation.
- Non-OpenAI provider prompt evidence is either validly credential-smoked or explicitly accepted as deferred release risk; Kimi-for-coding currently satisfies the required additional-provider evidence path.
- The remaining release operations are commit, tag, and external release publication steps when explicitly requested.

## Not In This Cut

- New major features.
- Risky refactors not required for v1 stability.
- Post-MVP items such as HTTP daemon mode, plugin marketplace, or multi-agent orchestration.
