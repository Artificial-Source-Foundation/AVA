# AVA 1.0 Backend MVP

AVA 1.0 is the current backend MVP baseline. In the current planning vocabulary, MVP and 1.0 mean the same capability cut.

The compiled project/runtime version reports `1.0.0`. This historical 1.0 baseline follows the 0.90 release-candidate re-audit, OpenAI and Kimi-for-coding live provider evidence, focused/full automated validation, and a deliberate release-bump slice. These docs do not publish a release by themselves: tag, binary artifact, package, and external release publication steps still require explicit manual action. Current Linux packaging closure is documented separately in [`../release-checklist.md`](../release-checklist.md): only strict source-built x86_64/x64 artifacts are qualified; ARM/non-x86 provenance remains unqualified.

## Release Status

- Runtime version: `1.0.0`.
- Provider release evidence: OpenAI and Kimi-for-coding live prompt smokes passed; Kimi-for-coding is accepted as the additional production-quality provider path for 1.0.
- Follow-up provider breadth: Anthropic remains auth-blocked by the configured key, while Moonshot and OpenRouter-compatible prompt smokes remain credential-blocked until credentials are available.
- Release operations still require an explicit user request for commit, tag, branch, push, or external release publication.

## Baseline Definition

AVA 1.0 was declared when the backend became stable enough for real local coding-agent use across interactive, print, and RPC workflows, with provider breadth beyond OpenAI and a small safe local extension foundation.

## Required Capabilities

- OpenAI remains excellent and at least one additional provider path is production-quality.
- Provider registry, model catalog, pricing/usage metadata, provider error normalization, and provider capability enforcement are stable.
- Provider-native tool/result/reasoning semantics are preserved or safely pruned before invalid requests are sent.
- Reasoning/thinking controls and lifecycle events exist for supported models and fail closed for unsupported models.
- Mid-session model switching, model-change entries, reasoning-control entries, session stats, compaction, export, and permission audit entries are durable and inspectable.
- Built-in tools are safe, bounded, permissioned, cancellable where practical, and covered by focused tests.
- Print mode and JSONL RPC protocol v1 are stable enough for automation clients and editor integrations.
- Local plugins and MCP stdio servers use explicit manifests/configuration, versioned out-of-process protocols, permission gates, audit labels, diagnostics, docs, samples, and regression tests.
- Release verification passes: normal build, full CTest, sanitizer build when practical, focused headless/live smokes, and whitespace/diff checks.

## Post-baseline behavior change — M0 permission hardening

The original M0 always-Ask/no-containment policy has since been superseded by a
sealed three-level command policy. Verified Standard path-bearing or mutable
plans use narrow Linux containment; Sensitive plans use it after approval, and
some Critical/Raw plans use it when a verified local plan and mutable-code policy
require it. Sensitive and Critical commands still ask for explicit approval, as
does any path where containment is unavailable. This is not a general AVA
sandbox: untrusted repositories still require OS/container/VM containment.

## Post-1.0 Roadmap

- HTTP/server daemon mode.
- Persistent cross-session permission rules have landed in current backend/RPC; remaining work is richer rule-management UX and broader policy diagnostics.
- Session tree backend/RPC APIs for fork, clone, labels, names, and caller-supplied branch summaries have landed; remaining work is frontend/TUI tree workflows and provider-generated branch summaries.
- LSP symbols, definitions, references, pull/publish diagnostics, bounded full-text on-disk sync, and exact-global-opt-in installed-only `clangd` have landed; it is the sole automatic LSP recipe, every other server requires explicit configuration, and unsaved-buffer sync and presentation polish remain follow-up work.
- Image attachment replay/storage/provider serialization, TUI input, and RPC image input/import are implemented.
- Plugin package manager, marketplace, or remote install flow.
- Advanced remote MCP OAuth, subscriptions, sampling, and pagination.
- Cross-platform hard sandbox guarantees for arbitrary plugin executables.
- Broader built-in multi-agent orchestration. The native `task` subagent/background-job slice landed after this 1.0 cut; see `docs/versions/1.1.md`.
