# AVA 1.0 Backend MVP

AVA 1.0 is the shipped backend MVP release. In the current planning vocabulary, MVP and 1.0 mean the same release cut.

The compiled project/runtime version reports `1.0.0`. This release follows the 0.90 release-candidate re-audit, OpenAI and Kimi-for-coding live provider evidence, focused/full automated validation, and a deliberate release-bump slice.

## Release Status

- Runtime version: `1.0.0`.
- Provider release evidence: OpenAI and Kimi-for-coding live prompt smokes passed; Kimi-for-coding is accepted as the additional production-quality provider path for 1.0.
- Follow-up provider breadth: Anthropic remains auth-blocked by the configured key, while Moonshot and OpenRouter-compatible prompt smokes remain credential-blocked until credentials are available.
- Release operations still require an explicit user request for commit, tag, branch, push, or external release publication.

## Release Definition

AVA 1.0 ships when the backend is stable enough for real local coding-agent use across interactive, print, and RPC workflows, with provider breadth beyond OpenAI and a small safe local extension foundation.

## Required Capabilities

- OpenAI remains excellent and at least one additional provider path is production-quality.
- Provider registry, model catalog, pricing/usage metadata, provider error normalization, and provider capability enforcement are stable.
- Provider-native tool/result/reasoning semantics are preserved or safely pruned before invalid requests are sent.
- Reasoning/thinking controls and lifecycle events exist for supported models and fail closed for unsupported models.
- Mid-session model switching, model-change entries, reasoning-control entries, session stats, compaction, export, and permission audit entries are durable and inspectable.
- Built-in tools are safe, bounded, permissioned, cancellable where practical, and covered by focused tests.
- Print mode and JSONL RPC protocol v1 are stable enough for automation clients and editor integrations.
- Local plugins and MCP stdio servers use explicit manifests/configuration, versioned out-of-process protocols, permission gates, audit labels, diagnostics, docs, samples, and regression tests.
- Release verification passes: normal build, full CTest, sanitizer build when practical, focused headless/live smokes, and whitespace/diff checks.

## Post-1.0 Roadmap

- HTTP/server daemon mode.
- Persistent cross-session permission rules.
- Session tree UI, fork, clone, and branch summaries.
- Full LSP symbols, definitions, references, and richer code-intelligence UI.
- Image/file attachment reads for multimodal providers.
- Plugin package manager, marketplace, or remote install flow.
- Advanced remote MCP OAuth, subscriptions, sampling, and pagination.
- Cross-platform hard sandbox guarantees for arbitrary plugin executables.
- Built-in multi-agent/subagent orchestration.
